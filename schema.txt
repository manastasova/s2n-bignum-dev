AES-256-GCM Tail Verification — Status Update

  Since the last update (per-band tail equivalence machine code == karatsuba_Nblocks == ghash_polyval_acc), the work has been
  assembled into a single top-level theorem, AES256_GCM_ENCRYPT_CORRECT, which proves the one binary aes256_gcm_mc correct for
  every input length val len ≤ 128 against the GCM spec — byte_list_at (aes256_gcm_encrypt (val len) pt_in ivec rks) out_ptr len
  for the ciphertext and read xi_ptr = gcm_final_xi (val len) pt_in ivec rks xi h for the tag. It is structured as a three-layer
  call chain. 
    - Top (dispatch): AES256_GCM_ENCRYPT_CORRECT's own proof is just a nested ASM_CASES_TAC cascade on val len at 16, 32,
  …, 112, with one XTS-style one-liner per band — MP_TAC AES256_GCM_ENCRYPT_LT_NBLOCK_ABS THEN DISCH_THEN MATCH_MP_TAC THEN
  ASM_REWRITE_TAC[] THEN ASM_ARITH_TAC — routing each length to its band lemma (9 bands, 0–8 blocks). 
    - Middle (abstract band): each
  AES256_GCM_ENCRYPT_LT_NBLOCK_ABS restates the band in spec vocabulary under one uniform 8-block precondition (so the dispatch
  is uniform), and its proof MP_TACs the concrete band lemma and lifts the raw-word result to spec form via OUT_BRIDGE_GEN
  (per-block 128-bit stores ⟹ byte-level byte_list_at (aes256_gcm_encrypt …)), GHASH_BLOCKS_N (the block list for that length
  range), and GCM_FINAL_XI_UNFOLD (fold into gcm_final_xi), with the frame/precondition reshaped by the sandwich lemmas
  ENSURES_FRAME_SUBSUMED / ENSURES_POSTCONDITION_THM / ENSURES_PRECONDITION_THM. 
    - Bottom (concrete band):
  AES256_GCM_ENCRYPT_LT_NBLOCK_CONCRETE is the only place the instructions actually run — proved by symbolic simulation
  (GCM_INIT_TAC → GCM_PROLOGUE_TAC → GCM_RUN → length-cascade → NBLOCK_MASK_REG collapsing the runtime mask-build →
  ABBREV_FINAL_XI_TAC freezing the GHASH accumulator to dodge byte-explosion → ENSURES_FINAL_STATE_TAC) — and its GHASH conjunct
  is discharged by the per-band closer that strings the tail equivalence together (e.g. GCM_2BLOCK_GHASH_VIA_BRANCH_TAC: reach
  ghash_Nblock_karatsuba via GHASH_NBLOCK_AS_NBLOCK, apply the per-N bridge GHASH_NBLOCK_KARATSUBA_EQ_POLYVAL_ACC, finish XOR-AC
  with bubble_sort_conv). The whole file loads clean end-to-end — AES256_GCM_ENCRYPT_CORRECT proves with hyps=0 and no added
  axioms/cheats.
